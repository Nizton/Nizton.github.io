# Мои сайты

Публичное портфолио доступно по адресу https://nizton.github.io/.

## Публикация на GitHub Pages

Изменения в ветке `main` запускают `.github/workflows/pages.yml`. Workflow устанавливает зависимости через `npm ci`, проверяет типы, линтер и тесты, собирает `dist` и публикует его на GitHub Pages. В настройках репозитория источником Pages выбран GitHub Actions.

Чтобы обновить работу, измените `src/projects.ts` и изображения в `public/images`, затем отправьте коммит в `main`. Услуги и контакт редактируются в `src/offer.ts`.

Сайт услуг по созданию сайтов с портфолио и стартовой ценой от 5 000 ₽. Статический HTML генерируется из TypeScript. Node.js 24+, npm. Небольшой скрипт обработки ошибок изображений подключается только при наличии превью.

## Цена и контакт

Услуги, цены и будущая ссылка на Telegram находятся в `src/offer.ts`. Одностраничный сайт от 5 000 ₽, многостраничный от 10 000 ₽, интернет-магазин от 20 000 ₽. Минимальная цена на обложке вычисляется из коллекции услуг. Чтобы добавить контакт, заполните `contact` по комментарию в файле. До его добавления раздел связи честно сообщает о состоянии.

## Открыть

```powershell
cd C:\Nizton-m\Nizton
npm ci
npm run dev
```

Откройте http://127.0.0.1:4173. После изменения коллекции dev-сервер перезапускается, страницу нужно обновить. Для CSS достаточно обновления страницы.

Если системный npm выдаёт `Cannot find module 'make-fetch-happen'`, используйте подготовленную локальную копию. Она закрывает сбой установленного npm на этой машине.

```powershell
node .tools/package/bin/npm-cli.js ci --ignore-scripts
node .tools/package/bin/npm-cli.js run dev
```

## Добавить работу

Добавьте одну запись в массив `projects` в `src/projects.ts`. Ниже показана схема записи с обозначениями для ваших реальных материалов.

```ts
{
  id: "stable-project-id",
  title: "Название вашего сайта",
  url: "https://ВАШ-ДОМЕН",
  description: "Короткое описание реальной работы.",
  preview: {
    src: "/images/your-site.webp",
    alt: "Описание показанного экрана вашего сайта",
    width: 1440,
    height: 900,
  },
},
```

`id`, `title` и `url` обязательны. `description` и `preview` можно опустить. Сохраните устойчивый ID при переименовании сайта. Порядок массива задаёт порядок работ. URL допускает HTTP/HTTPS, встроенные логин и пароль отклоняются. Невалидные данные останавливают сборку с ошибкой.

Необязательное поле `details` добавляет детали кейса. Каждая запись содержит `title`, `description` и необязательное `preview` того же формата. В записи FORMA уже есть пример с мобильным экраном и калькулятором. Компоненты и CSS менять не требуется.

Изображение положите в `public/images`. Укажите его реальные размеры. Превью кадрируется сверху в формате 16:10. Первый снимок загружается сразу, следующие отложены. Ошибка изображения оставляет видимую ссылку на сайт. Подбирайте скриншот после проверки читаемости на телефоне.

Первое превью также показывается на обложке и загружается сразу. Основное превью в кейсе и изображения деталей загружаются отложенно. FAQ использует нативные `details`/`summary`, работает с клавиатуры и при выключенном JavaScript.

## Проверить и собрать

```powershell
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:browser
npm run preview
```

Браузерные тесты используют установленный Microsoft Edge. Тестовые проекты существуют только в тестовых маршрутах и не попадают в `dist`. Снимки и локальные метрики сохраняются в `artifacts/qa`.

Готовый `dist` можно разместить на статическом хостинге в корне домена. Внешние сайты открываются в текущей вкладке, стандартные Ctrl/Cmd+клик и контекстное меню доступны.
